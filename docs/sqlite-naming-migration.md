# SQLite naming migration inventory

Inventory from scratch copies of `atlas.sqlite` and `atlas-cache.sqlite`, using `sqlite_schema` and `pragma_table_info` through Node `DatabaseSync`. The copies can predate current source: in particular the current `dataset_payloads` writer stores `bytes` and `gzip`, while the copied cache has `payload`. References below identify source locations, not an exhaustive list of tests. Column rows inherit their table writer and readers.

`dataset_catalogue` describes compiled catalogue outputs and hashes, distinct from the statistics `dataset` entity. `area_inventory_entry` is a projection of `area` and `area_version`, not a second area table. Metadata tables use singular collective nouns, such as `area_search_meta`, and need no rename. Compatibility views retain old names and columns when a migration is implemented.

## Out of scope

The postcode layout branch handles `postcodes`, `postcode_area_codes`, `postcode_area_columns`, `postcode_area_matches`, `postcode_area_matches_decoded`, `postcode_area_releases`, `postcodes_decoded`, `postcode_counts`, and the current source’s `postcode_area_set`. This includes every camelCase and release-qualified column in those objects.

The election branch handles `election`, `contest` and `candidacy`. The compression branch owns the contents and format of `dataset_payloads` and `payloads`, table renames only are in scope here.

The `areas` view is used by postcode readers and DuckDB postcode-count queries, so its replacement must be coordinated with the postcode layout branch.

## Compatibility table names

These original names already follow singular snake_case, but retaining their old
column spellings requires the original name to become a view. The underlying
names distinguish the single inventory header from coverage rows.

## Implementation status

The proposed renames are implemented with deprecated views except `area_releases`, `areas`, and `payloads`, which remain unchanged because of their broad use and overlap with other branches. For inventory and coverage tables already named in singular snake_case, the stored tables use `_metadata` or `_entry` so the old name can remain a compatibility view with its old column spellings.
